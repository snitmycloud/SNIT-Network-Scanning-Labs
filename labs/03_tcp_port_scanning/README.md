## 4. TCP Scanning Concepts

### TCP Three-Way Handshake

The TCP connection process involves:

1. SYN: Client requests a connection.
2. SYN-ACK: Server acknowledges the request.
3. ACK: Client completes the connection.

### TCP Port States

| Port State | Meaning |
|---|---|
| Open | An application is accepting connections |
| Closed | The host responds, but no application is listening |
| Filtered | Nmap cannot determine the port state because probes are blocked or responses are insufficient |
| Unfiltered | Port is accessible, but Nmap cannot determine whether it is open or closed using the scan type |

## 5. Practical Exercises

### Exercise 1: Default TCP Scan

```bash
nmap <TARGET-IP>
```

Identify open TCP ports.

### Exercise 2: TCP SYN Scan

```bash
sudo nmap -sS <TARGET-IP>
```

**Explanation:** Sends TCP SYN probes and analyzes responses without completing the normal TCP handshake for open ports.

### Exercise 3: TCP Connect Scan

```bash
nmap -sT <TARGET-IP>
```

**Explanation:** Uses the operating system's TCP connect function to establish a full connection.

### Exercise 4: Scan Specific TCP Ports

```bash
nmap -sS -p 22,80,443 <TARGET-IP>
```

### Exercise 5: Scan a Port Range

```bash
nmap -sS -p 1-1000 <TARGET-IP>
```

### Exercise 6: Scan All TCP Ports

```bash
sudo nmap -sS -p- <TARGET-IP>
```

Use only against the assigned lab target.

## 6. TCP Traffic Analysis Using Wireshark

1. Open Wireshark on the Kali Linux lab interface.
2. Start packet capture.
3. Run an authorized TCP SYN scan.
4. Apply this display filter:

```text
tcp.flags.syn == 1
```

5. Observe SYN, SYN-ACK and RST responses.
6. Compare the traffic generated by SYN and Connect scans.

## 7. TCP Response Interpretation

| Response | Typical Interpretation |
|---|---|
| SYN-ACK | Port is open |
| RST | Port is closed |
| No response | Often filtered or otherwise inconclusive |
| ICMP unreachable | May indicate filtering or network restrictions |

Interpret results in the context of the scan type and network configuration.
